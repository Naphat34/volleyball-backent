# แนวทาง schema compatibility

ระบบยังมีตารางที่ซ้ำเชิงแนวคิดเพื่อรองรับข้อมูลเดิมและหน้าจอเดิม:

- `team_entries`: source of truth สำหรับการสมัครทีมเข้ารายการแข่งขัน รวมถึง category, gender, age group, roster และสถานะการอนุมัติ
- `team_competitions`: legacy mirror สำหรับหน้าจอ/query เดิมที่ยังอ่านความสัมพันธ์ทีมกับรายการแข่งขัน

กติกาการพัฒนาต่อ:

- โค้ดใหม่ควรอ่านข้อมูลการสมัครจาก `team_entries` ก่อน
- ถ้าการเปลี่ยนแปลงยังต้องรองรับหน้าจอเดิม ให้ mirror ค่าไปที่ `team_competitions` ใน transaction เดียวกัน
- ห้ามเพิ่ม field ใหม่ซ้ำในทั้งสองตารางโดยไม่มีเหตุผลด้าน backward compatibility
- migration ใหม่ควรระบุชัดเจนว่า field ใดเป็น canonical และ field ใดเป็น compatibility mirror
- เมื่อหน้าจอเก่าถูกย้ายมาใช้ `team_entries` ครบแล้ว จึงค่อยวาง migration สำหรับเลิกใช้ `team_competitions`

จุดที่ต้องระวังเป็นพิเศษ:

- การสมัคร/ยกเลิกสมัครรายการแข่งขัน
- การอนุมัติสถานะทีมในรายการแข่งขัน
- การสร้าง fixture หรือ match จากรายชื่อทีมที่ approved
- การลบทีมและลบรายการแข่งขัน ซึ่งต้องลบข้อมูลทั้งสองตารางให้ตรงกัน
