# ขั้นตอนที่ 4 — หน้าจอผู้ดูแลสามส่วน

วันที่ 16 พฤศจิกายน 2026

พัฒนาตามคำยืนยันให้ทั้งสามส่วนใช้หน้าตาใหม่และโครงร่วมกัน โดยคงหน้าที่และขอบเขตสิทธิ์ที่ยืนยันในขั้นตอนที่ 2 และ migration 004 ไม่มี migration เพิ่มในขั้นตอนนี้

## ทางเข้าของแต่ละส่วน

| บทบาท | URL | ขอบเขตหน้าจอ |
|---|---|---|
| super_admin | `/admin` | ข้อมูลกลาง รายการแข่งขัน ทีม บุคลากร รายงาน บัญชีและสิทธิ์ทั้งระบบ |
| super_admin_scorer | `/scorer-admin` | ภาพรวมคะแนน แมตช์ คิวตรวจรับ ประวัติ และผู้บันทึก Scorer ในรายการที่ได้รับสิทธิ์ |
| super_admin_vims | `/vims-admin` | ภาพรวมสถิติ แมตช์ คิวตรวจรับ ประวัติ และผู้บันทึก VIMS ในรายการที่ได้รับสิทธิ์ |

`/access-center` ยังใช้ได้ ลิงก์เดิมของผู้ดูแลส่วนงานจะส่งไปพื้นที่ใหม่พร้อม query ของหน้าเดิม ส่วน Super Admin ใช้หน้านี้จัดการสิทธิ์และติดตามการตรวจรับทั้งสองส่วน ผู้บันทึกยังใช้แดชบอร์ด Scorer/VIMS เดิม

## สิ่งที่เปลี่ยน

- `AdminWorkspaceShell` ใช้ sidebar, header, ชื่อพื้นที่, โปรไฟล์, ภาษา, ธีม และสถานะออนไลน์ร่วมกัน มีเมนูมือถือและลิงก์ข้ามไปเนื้อหา
- Super Admin เปลี่ยนโครงภายนอก แต่ใช้ฟังก์ชันจัดการแข่งขันและ Master Data เดิมต่อ เมนูภายในใช้ query เช่น `/admin?view=accounts` เพื่อเปิดลิงก์ตรงและใช้ Back/Forward ได้
- Scorer Admin และ VIMS Admin มี Dashboard แยก ตัวกรองรายการ และจำนวนงานตามข้อมูลที่ API อนุญาต คำนวณงานรอตรวจจากฉบับล่าสุดต่อแมตช์และส่วนงาน ไม่บวกซ้ำจากประวัติเก่า
- แยกคิวฉบับล่าสุดกับประวัติทุกฉบับตามคำยืนยัน ประวัติอ่านได้แต่ไม่มีปุ่มเปลี่ยนผล ปุ่มตรวจรับยังตรวจ revision/scope และผู้ตรวจที่ API ตามเดิม
- ตารางแมตช์ค้นหาชื่อทีม รายการ หรือ ID ได้ แสดงสถานะภาษาไทยและหมายเลขแมตช์
- แมตช์ VIMS ที่สร้างเองแสดงเฉพาะสรุปในตารางตามคำยืนยัน ไม่เปิดหน้ารายละเอียดผู้ดูแลใหม่ และไม่พาไปหน้าคอนโซลผู้บันทึก ข้อมูลสรุป API ประกอบด้วยชื่อแมตช์/ทีมและสถานะ ไม่ส่ง payload เหตุการณ์ทั้งก้อนไปตาราง
- ผู้ดูแลส่วนงานเลือกได้เฉพาะบทบาทผู้บันทึกของตน ไม่มีปุ่มระงับทั้งบัญชี/เปลี่ยนบทบาท/รีเซ็ตรหัสผ่าน บังคับเลือกรายการแข่งขันอย่างน้อยหนึ่งรายการในแบบฟอร์มให้ตรงกับข้อห้ามเดิมของ API; Super Admin ยังสร้างบัญชีที่รอมอบรายการได้
- `AdminWorkspaceGate` ตรวจ session จากเซิร์ฟเวอร์ก่อนเปิด controls และตรวจซ้ำเมื่อกลับมา focus ปฏิเสธบัญชีที่หมดสิทธิ์ แม้ค่า role ที่ cache ไว้ยังเก่า
- ผู้ดูแลทั้งสามยังไม่มีสิทธิ์เข้าคอนโซลบันทึกคะแนนหรือสถิติ ทางเข้าผู้บันทึกและ Offline ไม่เปลี่ยนเป็นพื้นที่ผู้ดูแล

## ผลตรวจ

| การตรวจ | ผล |
|---|---|
| Backend access-control regression | ผ่าน 26 รายการ |
| Client workspace summary / role routing / Offline routing | ผ่าน 19 รายการ |
| Client ESLint / production build | ผ่าน |
| Browser: Scorer Admin | เข้าพื้นที่ถูกต้อง เห็นเฉพาะรายการที่ได้รับสิทธิ์ คิวฉบับ 2 ไม่ซ้ำฉบับ 1 ประวัติอ่านอย่างเดียว และลิงก์ไป VIMS Admin ถูกส่งกลับพื้นที่ตน |
| Browser: VIMS Admin | Dashboard และสรุปแมตช์ตรงขอบเขต ไม่มีลิงก์ไปหน้าบันทึกจากแมตช์ VIMS สร้างเอง ผู้ใช้แสดงเฉพาะ VIMS operator และปุ่มสร้างถูกปิดจนเลือกรายการ |
| Browser: Super Admin | ใช้ shell ร่วมกัน เปิดเมนูจัดงานเดิมและศูนย์สิทธิ์ได้ เห็นรายการทั้งหมดในข้อมูลทดสอบ |
| Responsive | ตรวจ desktop 1366×900 และ mobile 390×844; เปิดเมนูและเลือกหน้าได้ คืน viewport หลังทดสอบ |

การทดสอบสามบทบาทใช้ schema ชื่อสุ่ม `volley_ui_test_*` ใน PostgreSQL local พร้อม backend 5001 และ frontend 5174 ชั่วคราว ไม่สร้างบัญชีสมมติหรือข้อมูลแข่งขันลง schema `volley` ของแอป ปิดบริการทดสอบและล้าง schema หลังจบ รูปหน้าจอทดสอบอยู่ `tmp/access-qa/step4/`

คำสั่งทดสอบ:

```powershell
# client
npm.cmd run test:admin-workspace
npm.cmd run lint
npm.cmd run build

# backend
npm.cmd run test:access-control
node --check controllers/accessController.js
```

ระบบหลัก local ยังมีบัญชี `super_admin` บัญชีเดียวและยังไม่มีรายการแข่งขัน การทดสอบด้วยข้อมูลตัวอย่างจึงไม่ใช่หลักฐานว่ามีข้อมูลแข่งขันจริงอยู่ในฐานหลัก ขั้นตอนนี้ไม่ได้สร้างบัญชีผู้ดูแล Scorer/VIMS จริงและไม่ได้ deploy ไป Online
