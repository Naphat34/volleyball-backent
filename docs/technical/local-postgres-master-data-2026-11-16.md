# PostgreSQL ในเครื่องและผลตรวจ Master Data ขั้นที่ 1

วันที่ดำเนินการ: 16 พฤศจิกายน 2026

## ผลลัพธ์

ตามที่ผู้ใช้ยืนยัน ได้สร้างฐานใหม่ `Volley_db2026` ใน PostgreSQL ในเครื่องพอร์ต 5432 โดยคัดลอก schema `volley` จากฐาน `postgres` ในเครื่อง เก็บฐานต้นทางเดิมไว้ ไม่ใช้ข้อมูลจาก Supabase และไม่ลบหรือเขียนทับฐานที่มีอยู่

ต้นทางในเครื่องมี 24 ตาราง แต่ทุกตารางไม่มีแถวข้อมูล การคัดลอกจึงได้โครงสร้างพร้อมใช้งานแต่ยังไม่มีข้อมูลอ้างอิง บัญชี ทีม นักกีฬา หรือประวัติการแข่งขัน ผล 160 แถวของ Supabase ที่รายงานก่อนหน้าเป็นคนละฐาน ห้ามนำมารวมเป็นผลตรวจฐานในเครื่อง

ใช้ PostgreSQL 18.7 `pg_dump` สำรองเฉพาะ schema `volley` แล้ว `pg_restore --single-transaction --exit-on-error` ลงฐานใหม่ ก่อนสร้างตรวจว่าชื่อฐานปลายทางยังไม่มีอยู่ ไม่ใช้ `--clean` หรือ drop database

## การตั้งค่าที่แก้แล้ว

เพิ่ม `DB_PROVIDER=postgres`, `DB_POSTGRES_PREVIEW=true`, `DB_PG_SCHEMA=volley` และใช้ค่าการเชื่อมต่อ PostgreSQL ในเครื่องจากตัวแปร DB_* เดิม คงชื่อฐาน `Volley_db2026` และพอร์ต 5432 ตามที่ผู้ใช้เลือก

บริการในเครื่องตอบว่าไม่รองรับ SSL จึงตั้ง `DB_SSL=false` เฉพาะ local environment นี้ ไม่ปิดการตรวจสอบใบรับรองสำหรับการเชื่อมต่อ Online รหัสผ่านอยู่ใน `.env` ที่ถูก ignore ไม่บันทึกลงเอกสารหรือ Git คงค่า JWT, PORT และ FRONTEND_URL เดิม

ปรับ `backend/config/postgres.js` ให้รับตัวแปรแยกได้ หากมี `DATABASE_URL` จะใช้ URL เป็นลำดับแรกตามพฤติกรรมเดิม ตรวจช่วงพอร์ตและไม่แสดง URL ที่ผิดรูปแบบพร้อมรหัสผ่านใน error message

## หลักฐานการตรวจรับ

| รายการ | ผล |
|---|---|
| Adapter ที่แอปโหลดจริง | PostgreSQL |
| current_database() | Volley_db2026 |
| current_schema() | volley |
| Parameter binding ผ่าน adapter | ผ่าน |
| ตาราง | 24 ตรงกับต้นทาง |
| คอลัมน์ | 372 ตรงกับต้นทาง |
| Constraints | 233 ตรงกับต้นทาง (รวม NOT NULL ตาม catalog ของ PostgreSQL 18) |
| Indexes | 126 ตรงกับต้นทาง |
| ฟังก์ชัน | 6 และ hash ตรงกับต้นทาง |
| Triggers ที่ไม่ใช่ภายใน | 2 และ hash ตรงกับต้นทาง |
| จำนวนแถวข้อมูล application | 0 ทั้งต้นทางและปลายทาง |
| Audit ที่ข้ามหรือ query ผิดพลาด | 0 |

เทียบ column/constraint/index metadata และ count ทุกตาราง รวมถึง hash นิยามฟังก์ชันและ trigger ต้นทาง/ปลายทางตรงกัน การตรวจ adapter ใช้ transaction READ ONLY และ rollback ไม่เพิ่มข้อมูลทดสอบในฐานจริง

ชุดทดสอบ:

- `npm.cmd run test:postgres`: ผ่าน 62, ข้าม 2, ไม่ผ่าน 0 (ส่วนใหญ่ใช้ PostgreSQL ในหน่วยความจำ ไม่ใช่การเขียนลงฐานที่สร้างใหม่)
- `node --test tests/postgresAdapter.test.js tests/masterDataAudit.test.js`: ผ่าน 6, ข้าม 1, ไม่ผ่าน 0
- `node --check` ไฟล์ JavaScript ที่แก้และ `git diff --check`: ผ่าน

## ผลตรวจความขาด/ซ้ำ/ไม่ได้ใช้งาน

| กลุ่ม | สิ่งที่พบ | ข้อเสนอขั้นต่อไป |
|---|---|---|
| บัญชี | users ว่าง | ต้องสร้างบัญชีเริ่มต้นตามแผนสิทธิ์ที่ตกลง; ยังไม่สร้างบัญชีหรือรหัสผ่านเริ่มต้นอัตโนมัติ |
| รุ่นอายุ | age_groups ว่าง | ทบทวนและเติมข้อมูลอ้างอิง U12/U14/U16/U18/Open จาก seed ที่มีอยู่เมื่ออนุมัติขอบเขต |
| สนาม/เจ้าหน้าที่ | ว่าง | เพิ่มข้อมูลจริงก่อนจัดตารางและมอบหมายงาน |
| ทีม/นักกีฬา | ว่าง | ลงข้อมูลจริงหรือระบุแหล่งนำเข้าแยกต่างหาก ไม่รวมข้อมูล Online โดยอัตโนมัติ |
| การแข่งขัน/รายชื่อ/คะแนน/สถิติ | ว่าง | ยังไม่มีข้อมูลสำหรับตรวจความครบถ้วนเชิงธุรกิจหรือประวัติซ้ำ |
| ข้อมูลซ้ำ/ความสัมพันธ์กำพร้า | ไม่พบตามกฎที่ตรวจ เพราะไม่มีแถว | ไม่ถือว่าทดสอบกฎธุรกิจทุกข้อหรือรับรองการใช้งานจริงแล้ว |
| ข้อมูลที่ไม่ใช้ | ยังยืนยันไม่ได้ | ตารางว่างไม่ใช่เหตุให้ลบตารางหรือเลิกฟีเจอร์ |
| Migration history | ต้นทางไม่มีประวัติที่ audit พบ | ทบทวน/adopt โครงสร้างที่มีอยู่ก่อนรัน migration; ห้ามรัน baseline ทับ schema นี้ |

ขั้นที่ 1 ยืนยันฐานหลักและสถานะข้อมูลจริงได้แล้ว แต่ระบบยังเข้าสู่ระบบไม่ได้จนกว่าจะมีบัญชี และยังไม่มีข้อมูลอ้างอิงสำหรับเริ่มรายการ งานถัดไปคือกำหนด/พัฒนาสิทธิ์สามส่วนและแผนสร้างข้อมูลเริ่มต้นตามลำดับ ไม่ใช่ลบข้อมูลซ้ำหรือย้ายจาก Online

ยังไม่ได้ restart process backend ที่เปิดค้างอยู่หรือทดสอบ browser/Socket.IO ไม่มีการแก้ frontend การตรวจ adapter ยืนยันค่าที่ backend เริ่มใหม่จะโหลดจาก `.env` หากไม่มี environment ภายนอก override
