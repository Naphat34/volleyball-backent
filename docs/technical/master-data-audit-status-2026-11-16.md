# สถานะการตรวจ Master Data — MySQL

> ข้อมูลล่าสุด: ผู้ใช้แจ้งว่าเคยย้ายไป PostgreSQL และตรวจพบหลักฐานการย้ายจริงแล้ว ดู `database-provider-verification-2026-11-16.md` ขั้นตอน MySQL ด้านล่างเป็นประวัติการวินิจฉัย ไม่ใช่ข้อสรุปว่าฐานหลักยังเป็น MySQL

วันที่: 16 พฤศจิกายน 2026

ผู้ใช้เลือกตรวจ MySQL จาก `backend/.env` แบบอ่านอย่างเดียว

## ผลการดำเนินการ

- เตรียม `backend/scripts/auditMasterData.js` และทดสอบกับ PostgreSQL ในหน่วยความจำผ่านแล้ว การทดสอบนี้ไม่ยืนยันการเชื่อมต่อหรือ dialect ของ MySQL จริง
- การเชื่อมต่อครั้งแรกถูกจำกัดด้วยสภาพแวดล้อม (`EACCES`)
- การเชื่อมต่อหลังได้รับสิทธิ์รันเพิ่มเติมหมดเวลา (`ETIMEDOUT`)
- ค่าตั้งปัจจุบันเลือก MySQL โดยค่าเริ่มต้น แต่ host เป็นเครื่องนี้และ port เป็น `5432` พร้อม TLS
- พอร์ต `5432` โดยทั่วไปใช้ PostgreSQL แต่หมายเลขพอร์ตเพียงอย่างเดียวไม่สามารถยืนยันชนิดฐานข้อมูลได้
- การตรวจ listener/process จาก session นี้ไม่พบรายการที่พอร์ต `3306` หรือ `5432` และไม่พบ process ชื่อ MySQL/MariaDB/PostgreSQL ผลนี้ไม่ยืนยันว่าไม่มีฐานข้อมูลใน container หรือเครื่องอื่น

## ขอบเขตที่ยังทำไม่ได้

ยังไม่ได้อ่าน schema หรือแถวข้อมูลจริง จึงยังไม่มีผลนับข้อมูล ข้อมูลซ้ำ ความสัมพันธ์กำพร้า หรือบัญชีที่ไม่มีสิทธิ์ และยังสรุปความครบถ้วนของ Master Data ไม่ได้

ไม่มีการแก้ `.env` สร้าง/แก้ตาราง รัน migration หรือเปลี่ยนข้อมูล ไม่มีรายงาน audit ข้อมูลจริงที่สำเร็จจากการเชื่อมต่อครั้งนี้

## ข้อมูลที่ต้องยืนยันก่อนดำเนินการต่อ

ยืนยันว่า MySQL ที่ต้องการตรวจอยู่ที่เครื่องนี้หรือเซิร์ฟเวอร์อื่น และพอร์ตที่ใช้งานจริง หากอยู่ในเครื่องนี้ต้องเปิดบริการฐานข้อมูลก่อน หากใช้ฐานอื่นให้ปรับไฟล์ตั้งค่าภายในเครื่องโดยไม่ส่งรหัสผ่านในแชต จากนั้นรัน audit ซ้ำตาม `docs/technical/master-data-audit.md`

ห้ามเปลี่ยนพอร์ตเป็น `3306` หรือสลับไป PostgreSQL โดยอัตโนมัติ เพราะยังไม่ได้ยืนยันเป้าหมายจากผู้ใช้

## การตรวจเพิ่มเติมหลังผู้ใช้ยืนยัน MySQL ในเครื่อง พอร์ต 5432

- ตรวจด้วยสิทธิ์เพิ่มเติม พบ Windows service `MySQL80` อยู่ในสถานะ Running
- ขณะตรวจพอร์ต 5432 พบ listener ของ process `postgres` (PID 14548) ไม่ใช่ `mysqld`; การลอง audit ซ้ำยังได้ `ETIMEDOUT`
- อ่านไฟล์ตั้งค่าของบริการ `C:\ProgramData\MySQL\MySQL Server 8.0\my.ini` เฉพาะ section/port พบ `[mysqld] port=3306` และ `mysqlx_port=33060`
- การตรวจ listener ล่าสุดพบ `mysqld` (PID 6040) ที่พอร์ต 3306
- สถานะ process/listener เป็นข้อมูล ณ เวลาตรวจ อาจเปลี่ยนได้

ยังไม่เปลี่ยน `.env` และยังไม่ลองอ่านฐานพอร์ต 3306 รอผู้ใช้ยืนยันการใช้ MySQL พอร์ตที่ตรวจพบก่อน ไม่มีผล audit ข้อมูลจริงในรอบนี้

## หลังได้รับอนุญาตให้ตรวจพอร์ต 3306

- ลองเชื่อมต่อด้วยบัญชี/ชื่อฐานเดิมและ override port เฉพาะในหน่วยความจำ ไม่แก้ `.env`
- ติดต่อ MySQL ได้ถึงขั้น TLS handshake แต่ได้ `HANDSHAKE_SSL_ERROR` ซึ่งตรวจพบว่าเกี่ยวข้องกับการตรวจใบรับรอง
- พบ CA สาธารณะที่ `C:\ProgramData\MySQL\MySQL Server 8.0\Data\ca.pem` แต่ session นี้อ่านไฟล์ไม่ได้ (`EPERM`) แม้รันด้วยสิทธิ์เพิ่มเติม ไม่ได้เปลี่ยน ACL หรือปิดการตรวจสอบใบรับรอง
- ยังไม่มีผล audit ข้อมูลจริง ต้องจัดเตรียม CA ที่อ่านได้ หรือให้ผู้ใช้อนุญาตแนวทางเชื่อมต่อเฉพาะเครื่องโดยไม่ใช้ TLS ก่อน
