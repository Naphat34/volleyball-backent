# รายชื่อนักกีฬาอัตโนมัติ

เจ้าหน้าที่แก้ไขรายชื่อ เบอร์เสื้อ และบทบาทที่หน้า Team Dashboard > จัดการนักกีฬา เพียงจุดเดียว รวมถึงการนำเข้าจาก Excel รายการแข่งขันใช้ปุ่ม **ดูรายชื่อนักกีฬา** แทนการเลือกและบันทึกจัดตัว

หมายเลขเสื้อของนักกีฬาที่ใช้งานอยู่ห้ามซ้ำภายในทีมเดียวกัน ไม่แยกตามรุ่นหรือประเภท ตรวจทั้งฟอร์ม Excel และ API และบังคับด้วย unique index ใน migration 41 ทีมอื่นใช้หมายเลขเดียวกันได้ นักกีฬาที่ปิดใช้งานยังเก็บเบอร์และประวัติเดิมไว้ แต่ไม่จองหมายเลขในทะเบียนปัจจุบัน

- เมื่อสมัครรายการ ระบบคัดลอกรายชื่อที่เปิดใช้งานและผ่านเพศ/อายุเข้าให้ทันที การเพิ่ม แก้ไข หรือปิดใช้งานนักกีฬาโดยทีมและแอดมินจะซิงก์รายการที่ยังเปิดอยู่ในธุรกรรมเดียวกัน
- ซิงก์เฉพาะรายการสถานะ `open` ก่อนวันเริ่มแข่งขัน ใช้วันที่จาก MySQL เป็นวันตัดรอบ ไม่มีวันปิดรับรายชื่อแยกจากสถานะการแข่งขันในรุ่นนี้
- รายชื่อจะล็อกถาวรเมื่อปิดรับสมัคร ถึงวันเริ่มแข่งขัน หรือแมตช์มีสถานะพ้น scheduled, match setup, lineup, action หรือ event แล้ว การเปิดรายการใหม่ไม่ปลดล็อกประวัติ
- เก็บสำเนาชื่อสองภาษา วันเกิด เพศ รูป และข้อมูลแสดงผลพื้นฐาน พร้อมเบอร์และบทบาทของรายการไว้ ไม่คัดลอกเลขบัตรหรือเอกสารส่วนตัว การแก้ทะเบียนทีมภายหลังไม่เปลี่ยนสำเนาที่ล็อกแล้ว
- รุ่น `U18` หมายถึงอายุไม่เกิน 18 ปีในวันเริ่มแข่งขัน (U12/U14/U16 เช่นเดียวกัน) รุ่น Open ไม่จำกัดอายุ หากใช้เกณฑ์ปีเกิดหรือวันตัดอายุอื่น ต้องปรับนโยบายก่อนใช้งาน
- หากสมัครหลายรุ่นในรายการชื่อเดียวกัน นักกีฬาจะลงรุ่นอายุน้อยที่สุดที่ผ่านเกณฑ์ กรณีรุ่นเท่ากันใช้ entry ที่สมัครก่อน และคงการลงรุ่นที่ล็อกไว้แล้ว ไม่ย้ายนักกีฬาจากรุ่นที่ล็อก
- หากวันเกิดไม่ครบ รุ่นอายุไม่รู้จัก เบอร์ซ้ำ บทบาทไม่ถูกต้อง หรือเกินจำนวนสูงสุด จะแสดงข้อผิดพลาดและไม่เผยแพร่รายชื่อบางส่วนของ entry นั้น เจ้าหน้าที่ต้องแก้ทะเบียนทีมแล้วเปิดดูใหม่
- การเลือกผู้เล่นและบทบาทรายแมตช์เก็บใน `matches.match_setup` แยกจากรายชื่อรายการ ผู้บันทึกคะแนนเพิ่ม/แก้ทะเบียนนักกีฬาในรายการโดยตรงไม่ได้

## การติดตั้งและตรวจสอบ

ใช้ migration `40_add_automatic_entry_rosters.sql` หลัง migrations เดิม สำรองข้อมูลและตรวจสถานะ migration ของฐานข้อมูลเป้าหมายก่อนติดตั้ง ไม่เรียก migrations เก่าซ้ำกับฐานข้อมูลที่ไม่มีประวัติครบถ้วน

ข้อมูลรายการเดิมที่ปิดหรือเริ่มแล้วจะเก็บรายชื่อที่มีอยู่ ไม่เติมจากทะเบียนล่าสุดย้อนหลัง การ backfill ชื่อใช้ข้อมูลปัจจุบัน ณ วัน migration จึงไม่สามารถกู้ชื่อก่อนการแก้ไขในอดีตได้

ทดสอบจากโฟลเดอร์ backend: `npm.cmd run test:rosters`

ทดสอบ MySQL ด้วยข้อมูลชั่วคราวใน transaction และ rollback: ตั้ง `RUN_ROSTER_MYSQL=1` แล้วรัน `node --test tests/automaticEntryRoster.mysql.test.js`
