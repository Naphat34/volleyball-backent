# ศูนย์ส่งตรวจงาน VIMS

ผู้ใช้ `vims_operator` เปิด `/access-center` เพื่อดูแมตช์ในขอบเขต แยกสถานะแข่งขันออกจากสถานะตรวจรับ มีตัวกรองประเภท สถานะงาน ค้นหา และแบ่งหน้า

ปุ่มตรวจสอบเปิดหน้าต่างรายละเอียดเฉพาะงาน VIMS: สรุป รายชื่อ/ไลน์อัป สถิติ เหตุการณ์ ประวัติส่งตรวจ และความพร้อมก่อนส่ง ข้อมูลดึงจากเซิร์ฟเวอร์แบบอ่านอย่างเดียว เหตุการณ์แบ่งหน้า 100 รายการ ส่วนสถิติรวมคำนวณจากข้อมูลทั้งหมด ผู้ใช้ต้องยืนยันว่าตรวจข้อมูลแล้วและยืนยันส่งอีกครั้ง

กติกาที่ผู้ใช้ยืนยัน: แมตช์ทางการส่งตรวจได้เมื่อการแข่งขันจบและมีสถิติ แม้ VIMS ยังไม่จบให้เตือน ไม่บล็อก ระบบยังตรวจขอบเขต เจ้าของ/ผู้ได้รับมอบหมาย สิทธิ์ออฟไลน์ที่ค้าง และการส่งซ้ำบนเซิร์ฟเวอร์ แมตช์ VIMS สร้างเองคงกติกาเดิมว่าต้องจบและอยู่ในขั้น review

สถิติที่เปิดดูเป็นข้อมูลปัจจุบัน ไม่ใช่สำเนาย้อนหลังของแต่ละฉบับ ประวัติฉบับแสดงผู้ส่ง ผู้ตรวจ เวลา และเหตุผล ไม่อนุมานผู้บันทึกที่ไม่มีหลักฐาน และไม่เปิดเผย token เอกสารส่วนบุคคลหรือรายละเอียดอุปกรณ์ออฟไลน์ ข้อมูลที่ยังไม่ซิงก์จากเครื่องอื่นไม่สามารถยืนยันได้จากหน้านี้

เพิ่ม API อ่าน `GET /api/access/matches/:kind/:id/vims-detail?eventPage=1` โดยไม่เพิ่มสิทธิ์ให้บทบาทอื่น ไม่ต้องเพิ่ม migration ต้องอัปเดตทั้ง Backend และ Client

ทดสอบ Backend: `npm.cmd run test:vims-review` (ฐานข้อมูลจำลอง PGlite และ HTTP localhost)

ทดสอบ Client: `npm.cmd run test:access-language` พร้อม `npm.cmd run lint` และ `npm.cmd run build` ตัวทดสอบเบราว์เซอร์ใช้ข้อมูลจำลอง ไม่เขียนฐานข้อมูลจริง
