## เริ่มต้นและเข้าใจประเภทแมตช์

เข้าสู่ระบบด้วยบัญชีที่มีสิทธิ์บันทึกสถิติ แล้วเปิดหน้า VIS ที่ `/adminvis` หากไม่มีสิทธิ์หรือไม่พบแมตช์ ให้ผู้ดูแลตรวจสอบบัญชีและการเข้าถึงก่อนเริ่มงาน

ระบบมีแมตช์สองประเภท:

| ประเภท | ที่มา | การจัดการ |
| --- | --- | --- |
| ตารางแข่งขันจาก Admin | ผู้ดูแลสร้างแมตช์ ทีม และรายชื่อในระบบหลัก | กดดึงแมตช์จากเซิร์ฟเวอร์ การแก้ข้อมูลขึ้นกับสิทธิ์บัญชีและสถานะแมตช์ |
| สร้างเอง · VIS | สร้างจากแดชบอร์ด หรือนำเข้าไฟล์สำรอง | เก็บเป็นแมตช์แยก มีเจ้าของ สถานะตรวจสอบผล และการเปิดเผยแพร่ |

แมตช์สร้างเองเลือกบันทึกบนเซิร์ฟเวอร์หรือทำงานในเครื่องแบบ Offline ได้ เริ่มต้นเป็นส่วนตัว และไม่เพิ่มผลลงตารางคะแนนการแข่งขันหรือทะเบียนทีมหลักโดยอัตโนมัติ แมตช์ในเครื่องต้องกดซิงค์ก่อนข้อมูลจะขึ้นฐานข้อมูลและ Livescore

ขั้นตอนหลัก:

**เลือกหรือสร้างแมตช์ → ตรวจรายชื่อ → จัด P1–P6 → เลือกเสิร์ฟและฝั่ง → คีย์แรลลี่ → ตรวจประวัติ → ตรวจสถิติ → ส่งออก → ยืนยันผลและเผยแพร่ตามต้องการ**

## สร้างแมตช์ใหม่

### ขั้นตอน 1: ข้อมูลการแข่งขัน

กด **+ สร้างแมตช์ใหม่** แล้วระบุชื่อแมตช์หรือรายการแข่งขัน วันที่ เวลา สนาม ประเภททีม และจำนวนเซตสูงสุด

| รูปแบบ | เงื่อนไขชนะ |
| --- | --- |
| 3 เซต | ชนะ 2 เซต |
| 5 เซต | ชนะ 3 เซต |

### ขั้นตอน 2: ทีมและรายชื่อ

ระบุชื่อเจ้าบ้านและทีมเยือน แล้วเพิ่มรายชื่อด้วยการคัดลอกจากแมตช์เดิม นำเข้า Excel หรือวางตารางจาก Excel ตรวจรายชื่อแยกแต่ละทีมให้ครบก่อนกดถัดไป

การนำเข้าหรือใช้รายชื่อที่วางจะ **แทนที่รายชื่อทีมที่เลือก** จึงควรตรวจจำนวนผู้เล่นและเบอร์หลังทำรายการทุกครั้ง

### ขั้นตอน 3: ตรวจสอบและบันทึก

ตรวจชื่อแมตช์ ชื่อทีม จำนวนผู้เล่น วันที่ สนาม และรูปแบบเซต แล้วเลือก:

- **บันทึกฉบับร่าง**: เก็บข้อมูลไว้เพื่อกลับมาเตรียมต่อ
- **บันทึกและเริ่มคีย์**: บันทึกและเปิดหน้าลงสถิติ ต้องมีผู้เล่นทั่วไปที่ไม่ใช่ L อย่างน้อยทีมละ 6 คน

ก่อนเริ่มบันทึกสามารถกลับมาแก้ทีมและรายชื่อจากแดชบอร์ดได้ หลังเริ่มบันทึกข้อมูลส่วนนี้จะถูกล็อก

## เตรียมและนำเข้ารายชื่อ Excel

### รูปแบบไฟล์

ใช้ปุ่ม **ดาวน์โหลดแบบฟอร์ม Excel (.xlsx)** ในขั้นตอนรายชื่อ จะได้ไฟล์ `VIS_roster_template.xlsx` มีแผ่นงาน `home` และ `away`

| คอลัมน์ | ต้องมี | ตัวอย่างและความหมาย |
| --- | --- | --- |
| `number` | ต้องมี | `7` หมายเลขเสื้อจำนวนเต็ม 1–999 ไม่ซ้ำภายในทีม |
| `first_name` | ต้องมี | `สมชาย` |
| `last_name` | ต้องมี | `ใจดี` |
| `position` | ไม่บังคับ | `S`, `OH`, `MB`, `OPP`, `OP`, `L` |
| `captain` | ไม่บังคับ | `1`, `true`, `yes`, `C` หรือ `ใช่` เพื่อระบุกัปตัน |

รองรับหัวคอลัมน์ภาษาไทย **เบอร์ / ชื่อ / นามสกุล / ตำแหน่ง / กัปตัน** ด้วย

ตัวอย่าง:

| number | first_name | last_name | position | captain |
| --- | --- | --- | --- | --- |
| 3 | ธนา | ใจดี | S | 1 |
| 7 | กิตติ | มั่นคง | OH | |
| 9 | วัฒนา | รุ่งเรือง | MB | |
| 12 | นรินทร์ | สุขใจ | L | |

ตำแหน่งในรายชื่อเป็นบทบาทนักกีฬา ส่วน P1–P6 เป็นตำแหน่งการหมุนในไลน์อัป เช่น ผู้เล่นบทบาท S อาจเริ่มที่ P2 ได้ อย่าสับสนกับรหัส `S` ในช่องคีย์ ซึ่งหมายถึงการเสิร์ฟ

### นำเข้าจากไฟล์

1. กรอกข้อมูลแต่ละทีมในแผ่นงานที่ถูกต้อง แล้วบันทึกเป็น `.xlsx`
2. ที่ส่วนเจ้าบ้าน เลือกไฟล์ ระบบอ่านแผ่นงาน `home` หากพบ มิฉะนั้นอ่านแผ่นงานแรก
3. ที่ส่วนทีมเยือน เลือกไฟล์ ระบบอ่านแผ่นงาน `away` หากพบ มิฉะนั้นอ่านแผ่นงานแรก
4. ตรวจตารางตัวอย่าง เบอร์ ชื่อ ตำแหน่ง และเครื่องหมาย `(C)`
5. เมื่อครบทั้งสองทีมจึงบันทึกแมตช์

ข้อกำหนด: ไม่เกินทีมละ 30 คน ไฟล์ไม่เกิน 5 MB ชื่อและนามสกุลต้องครบ กัปตันไม่เกินหนึ่งคนต่อทีม ใช้ข้อความหรือตัวเลขธรรมดา ไม่ใช้สูตร ลิงก์ หรือข้อความแบบ rich text ในเซลล์ ไฟล์ `.xls` และ `.csv` ต้องแปลงเป็น `.xlsx` ก่อนใช้ช่องนำเข้าไฟล์นี้

### วางตารางจาก Excel

1. เลือกหัวคอลัมน์และแถวข้อมูลใน Excel แล้วคัดลอก
2. วางในช่องของทีมที่ต้องการ ข้อมูลต้องคั่นคอลัมน์ด้วย Tab
3. กด **ตรวจสอบและใช้รายชื่อที่วาง**
4. แก้แถวที่ระบบแจ้งผิด แล้วตรวจตารางตัวอย่างอีกครั้ง

## เปิดไฟล์สำรอง

ใช้เพื่อเปิดข้อมูลเก่าหรือสร้างสำเนาสำหรับทำงานต่อ

1. เลือก **นำเข้า JSON**, **เปิดไฟล์ .seava** หรือ **ไฟล์บนเว็บ**
2. เลือกไฟล์หรือโหลดลิงก์ HTTPS
3. ตรวจชื่อแมตช์ ทีม จำนวนผู้เล่น และจำนวนเหตุการณ์ในตัวอย่าง
4. กด **นำเข้าและเปิดแมตช์**
5. ตรวจคะแนน ไลน์อัป และประวัติหลังนำเข้า

การนำเข้าสร้าง **แมตช์ส่วนตัวใหม่** ไม่เขียนทับแมตช์ต้นฉบับ ระบบคำนวณคะแนนใหม่จากเหตุการณ์ ไม่คัดลอกเจ้าของ สถานะเผยแพร่ หรือการยืนยันผลเดิม ไฟล์ที่เล่นจบแล้วต้องตรวจสอบก่อนยืนยันอีกครั้ง

ไฟล์ต้องเป็นรูปแบบสำรอง VOLLEY VIS ที่รองรับและไม่เกิน 5 MB การเปลี่ยนนามสกุลไฟล์อย่างเดียวไม่ทำให้ไฟล์จากโปรแกรมอื่นใช้งานได้ ไฟล์เก่าที่ไม่มีโครงสร้างแรลลี่อาจนำเข้าไม่ได้ สำหรับไฟล์บนเว็บ เว็บต้นทางต้องอนุญาตการอ่านข้ามเว็บไซต์ (CORS)

## จัดไลน์อัปและเลือกทีมเสิร์ฟ

หน้าจัด Lineup จะปรากฏเมื่อเซตยังไม่มีข้อมูลเริ่มต้นที่ครบถ้วน

1. เลือกผู้เล่นครบ P1–P6 ของทั้งสองทีม แต่ละทีมต้องไม่เลือกคนซ้ำ
2. ตรวจตำแหน่งจากมุมมองแดนของทีมนั้น แดนหน้าเรียง P4–P3–P2 และแดนหลังเรียง P5–P6–P1
3. ใช้ **หมุนปกติ / หมุนย้อน** หากต้องเลื่อนลำดับผู้เล่นทั้งชุดก่อนบันทึก
4. หากมีขั้นตอนเลือกเสิร์ฟ ให้เลือกทีมเสิร์ฟก่อน ผู้เล่น P1 ของทีมนั้นจะเป็นผู้เสิร์ฟ
5. เลือกทีมที่อยู่ซ้ายและขวาจากมุมมองผู้บันทึก หากหน้าจอร้องขอ
6. กด **บันทึกและเริ่มลงสถิติ**

เมื่อเริ่มเซตใหม่ให้ตรวจและจัดไลน์อัปของเซตนั้นตามหน้าจอ เซตแรกและเซตตัดสินมีขั้นตอนเลือกเสิร์ฟและฝั่ง ส่วนเซตอื่นระบบใช้ข้อมูลลำดับเซตประกอบ

`*` และ `a` ผูกกับเจ้าบ้าน/ทีมเยือนเสมอ แม้ทีมเปลี่ยนไปอยู่คนละด้านของสนาม

## พื้นที่ทำงานและแถบเครื่องมือ

พื้นที่หลักประกอบด้วยคะแนนด้านบน สนามตรงกลาง Bench ของแต่ละทีม ช่องคีย์ และแผงโค้ดและประวัติ ด้านล่างสุดของ Bench มีปุ่มเวลานอกและเปลี่ยนตัว

| ปุ่ม | การทำงาน |
| --- | --- |
| ← รายการแมตช์ | กลับแดชบอร์ด ข้อความที่ยังไม่ได้บันทึกไม่ถือเป็นประวัติ |
| `</>` | Code หลัก ให้น้ำหนักพื้นที่แผงคีย์ |
| ▶ | Video หลัก เปิดแผงวิดีโอและให้น้ำหนักพื้นที่วิดีโอ |
| ◫ | เปิดแผงวิดีโอและแบ่งแผง Code/Video เท่ากัน |
| ▥ / ☰ | จัดแผง Code/Video ซ้าย–ขวา หรือบน–ล่าง |
| ↺ | คืนรูปแบบเริ่มต้น |
| ▣ สนาม | ซ่อนหรือแสดงสนามและ Bench |
| 🎥 แผงวิดีโอ | ซ่อนหรือแสดงวิดีโอ |
| 📋 ตั้งค่าแมตช์ | ตรวจรายชื่อ เปลี่ยนสีทีมในหน้าบันทึก และตั้งค่าที่บัญชีมีสิทธิ์ |
| 📊 สถิติเต็ม | เปิดสถิติทั้งแมตช์และปุ่มรายงาน PDF |
| ⇪ แชร์ | คัดลอกลิงก์หน้าคีย์ ผู้รับต้องเข้าสู่ระบบและมีสิทธิ์แมตช์นั้น |
| ⤓ ส่งออก JSON | ดาวน์โหลดไฟล์สำรอง ไม่ใช่รายงานสำหรับพิมพ์ |
| LIVE | เปิดหน้าผลการแข่งขันเมื่อมีลิงก์ให้ใช้ |
| ลองส่งรายการค้างอีกครั้ง | ส่งรายการเดิมที่ยังไม่ยืนยันผลการบันทึก |

เมื่อแสดงวิดีโอ ลากหัวแผงไปยังอีกแผงเพื่อสลับตำแหน่ง หรือลากเส้นแบ่งเพื่อปรับสัดส่วน ปุ่มรูปแบบเหล่านี้ควบคุมแผง Code/Video ไม่ได้ปรับความกว้างประวัติด้านขวาโดยตรง

วิดีโอรองรับลิงก์ YouTube ลิงก์วิดีโอที่เบราว์เซอร์เล่นได้ และไฟล์วิดีโอในเครื่อง การเล่นขึ้นกับรูปแบบไฟล์และสิทธิ์ของแหล่งวิดีโอ การเลือกวิดีโอไม่สร้างเหตุการณ์สถิติอัตโนมัติ

การแก้ชื่อทีมในระบบหลักอาจมีผลต่อชื่อทีมที่ใช้ทั้งระบบ และต้องมีสิทธิ์ Admin ส่วนรายชื่อแมตช์สร้างเองให้แก้ผ่านแดชบอร์ดก่อนเริ่มบันทึก

## หลักการคีย์ VIS

### โครงสร้างรหัส

```text
ทีม + เบอร์ผู้เล่น + ทักษะ + ผล
*07S a04A/
```

ตัวอย่างนี้คือเจ้าบ้านเบอร์ 7 เสิร์ฟ แล้วทีมเยือนเบอร์ 4 ตบติดบล็อก ใช้ Space แยกเหตุการณ์ในแรลลี่เดียวกัน กด Enter เมื่อมีผลจบแต้มที่ถูกต้อง

| ตัวทีม | ความหมาย |
| --- | --- |
| `*` | เจ้าบ้าน |
| `a` | ทีมเยือน |

แนะนำใส่ตัวทีมให้ชัด โดยเฉพาะเมื่อสองทีมใช้เบอร์เหมือนกัน ระบบค้นทีมจากเบอร์ในสนามก่อน แล้วจึงรายชื่อ หากยังระบุไม่ได้แน่นอนจะใช้บริบทเหตุการณ์ประกอบ ต้องตรวจ Preview ทุกครั้ง ผู้เล่นที่บันทึกต้องอยู่ในไลน์อัปปัจจุบัน

### รหัสทักษะ

| รหัส | ทักษะ | ตัวอย่าง |
| --- | --- | --- |
| `S` | เสิร์ฟ | `*03S` |
| `R` | รับเสิร์ฟ | `a10R+` |
| `A` | ตบ / รุก | `*07A#` |
| `B` | บล็อก | `a09B#` |
| `D` | ขุดบอล / ป้องกัน | `*06D+` |
| `E` | เซต | `a02E#` |

### รหัสผลการเล่น

| ผล | ความหมาย | ผลต่อคะแนน |
| --- | --- | --- |
| `#` | ได้แต้มสำหรับ S/A/B; สมบูรณ์สำหรับ R/D/E | S/A/B จบแต้มให้ทีมผู้เล่น ส่วน R/D/E ยังไม่จบแต้ม |
| `+` | ผลบวก เล่นต่อได้ดี | ยังไม่จบแต้ม |
| `!` | เล่นต่อได้ | ยังไม่จบแต้ม |
| `-` | ผลลบ เล่นต่อยาก | ยังไม่จบแต้ม |
| `=` | ผิดพลาด | คู่แข่งได้แต้ม |
| `/` | ตบติดบล็อก ใช้กับ A เท่านั้น | คู่แข่งได้แต้ม |
| ไม่ใส่ผล | บันทึกการเล่นระหว่างแรลลี่ | ต้องคีย์ต่อจนมีผลจบแต้ม |

### รหัสระดับทีม

| รหัส | ความหมาย |
| --- | --- |
| `*OP#` | คู่แข่งผิดพลาด เจ้าบ้านได้แต้ม |
| `aOP#` | คู่แข่งผิดพลาด ทีมเยือนได้แต้ม |
| `*T=` | เจ้าบ้านผิดพลาด ทีมเยือนได้แต้ม |
| `aT=` | ทีมเยือนผิดพลาด เจ้าบ้านได้แต้ม |

OP/T ใช้เมื่อไม่ระบุผู้เล่น ไม่ต้องใส่เบอร์ และไม่เพิ่มแต้มให้สถิติรายบุคคล

### Preview ก่อนบันทึก

- `✓` แสดงรหัสที่อ่านได้ พร้อมทีม ผู้เล่น และการเล่น
- `✗` แสดงข้อผิดพลาด ต้องแก้ก่อนบันทึก
- แถวสีจางคือรหัสคู่ที่ระบบเติมหรือเสนอ
- ข้อความ `+1 ชื่อทีม (คะแนน)` แสดงทีมได้แต้มและคะแนนหลังบันทึก
- ถ้ามีผู้เสิร์ฟ ต้องเป็น P1 ของทีมที่มีสิทธิ์เสิร์ฟ
- ทั้งบรรทัดต้องลงผลได้แต้มให้ทีมเดียวกัน เช่น ตบติดบล็อกและบล็อกได้แต้มเป็นผลคู่กันได้ แต่ห้ามมีผลที่ให้แต้มคนละทีม

## ตัวอย่างการคีย์ทั้งแรลลี่

ตัวอย่างต่อไปนี้สมมติว่าเจ้าบ้านคือ THA ทีมเยือนคือ JPN และผู้เล่นตามเบอร์อยู่ในสนาม ผู้เสิร์ฟต้องตรงกับ P1 จริงของแต่ละแรลลี่

| พิมพ์หรือกด | ความหมาย / สิ่งที่ควรตรวจ |
| --- | --- |
| ช่องว่าง → Tab → `#` → Enter | เติมผู้เสิร์ฟปัจจุบัน แล้วบันทึกเอซ |
| `*03S=` | THA #3 เสิร์ฟเสีย แต้มให้ JPN |
| `*03S a10A#` | THA #3 เสิร์ฟ JPN #10 ตบได้แต้ม เลือกรหัสคู่ก่อน Enter |
| `*03S a 10#` | รูปย่อของตัวอย่างก่อนหน้า หลังเสิร์ฟระบบเดาทักษะเป็น A |
| `*07S a04A/` | JPN #4 ตบติดบล็อก เลือกผู้บล็อกของ THA หรือ OP# |
| `*07S a13A=` | JPN #13 ตบเสีย THA ได้แต้ม |
| `a06S *11A a14B#` | THA #11 ตบ JPN #14 บล็อกได้แต้ม ระบบเติมผล `/` ให้ผู้ตบที่ยังไม่มีผล |
| `*OP#` | เจ้าบ้านได้แต้มจากความผิดพลาดคู่แข่งโดยไม่ระบุผู้เล่น |
| `aT=` | ทีมเยือนเสียเอง แต้มให้เจ้าบ้าน |

ตัวอย่างคีย์ครบหลายทักษะ:

```text
*03S a10R+ a02E# a04A#
```

THA #3 เสิร์ฟ → JPN #10 รับดี → JPN #2 เซตสมบูรณ์ → JPN #4 ตบได้แต้ม เมื่อ Enter ทั้งแรลลี่เพิ่มคะแนนให้ JPN เพียงหนึ่งแต้ม

การพิมพ์แค่เบอร์กับผลในเหตุการณ์แรกอาจถูกตีความเป็นเสิร์ฟ เช่น `3=` จึงควรเขียนทักษะและทีมเต็มเมื่อต้องการระบุการตบโดยไม่มีเหตุการณ์เสิร์ฟนำหน้า เช่น `a04A#`

**บล็อกต้องใส่ B** เช่น `a09B#` การพิมพ์ `9#` หลังเสิร์ฟจะถูกตีความเป็นการตบ ไม่ใช่บล็อก

## คำแนะนำรหัสฝั่งตรงข้าม

| เหตุการณ์จบแต้ม | รหัสคู่ / ตัวเลือก |
| --- | --- |
| `S#` | `T=` ของคู่แข่ง เป็นรหัสคู่อัตโนมัติ |
| `S=` | `OP#` ของคู่แข่ง เป็นรหัสคู่อัตโนมัติ |
| `A#` | `T=` หรือผู้เล่นแดนหน้าคู่แข่ง `B=` |
| `A=` | `OP#` ของคู่แข่ง เป็นรหัสคู่อัตโนมัติ |
| `A/` | `OP#` หรือผู้เล่นแดนหน้าคู่แข่ง `B#` |
| `B#` | `T=` หรือผู้ตบคู่แข่ง `A/` |
| `B=` | `OP#` หรือผู้ตบคู่แข่ง `A#` |
| `OP#` / `T=` | ไม่ต้องใส่คู่ |

ใช้ ↑/↓ หรือคลิกตัวเลือกเพื่อเลือก ตรวจ Preview ก่อนกด Enter เพราะ Enter รวมคำแนะนำที่เลือกอยู่ด้วย การกด Tab หรือ Space จะรับคำแนะนำเข้าไปในช่องคีย์ หากไม่ต้องการรหัสคู่ที่เสนอให้กด Esc

เมื่อพิมพ์รหัสจบแต้มของอีกฝ่ายที่สอดคล้องกันไว้แล้ว ระบบไม่เติมรหัสคู่ซ้ำ เช่น `a06S *11A a14B#` จะปรับผู้ตบเป็น `*11A/` โดยไม่ต้องเพิ่ม T=/OP# อีก

ข้อควรระวัง: กด Space ตอนมีคำแนะนำจะเป็นการรับคำแนะนำ หากต้องการพิมพ์รหัสของตัวเองต่อ ให้ปฏิเสธคำแนะนำด้วย Esc ก่อน

## ปุ่มลัดและปุ่มใต้ช่องคีย์

ปุ่มลัดต่อไปนี้ใช้ขณะที่โฟกัสอยู่ในช่องคีย์

| ปุ่ม | การทำงาน |
| --- | --- |
| Tab เมื่อช่องว่าง | เติมผู้เสิร์ฟ P1 ของทีมที่มีสิทธิ์เสิร์ฟ |
| Tab เมื่อมีคำแนะนำ | รับรหัสคู่ที่เลือก |
| Tab เมื่อไม่มีคำแนะนำ | เติมตัวทีมตรงข้ามกับเหตุการณ์ล่าสุด เพื่อพิมพ์รหัสต่อ |
| Space | แยกเหตุการณ์ หรือรับคำแนะนำที่เลือกอยู่ |
| ↑ / ↓ | เปลี่ยนตัวเลือกคำแนะนำที่ไม่ได้เป็นรหัสคู่อัตโนมัติ |
| Esc | ปฏิเสธคำแนะนำที่เลือกอยู่; หากไม่มีคำแนะนำที่ปฏิเสธได้ จะล้างช่องคีย์ |
| Enter | บันทึกทั้งแรลลี่รวมคำแนะนำที่เลือก เมื่อข้อมูลถูกต้องและมีผลจบแต้ม |
| ↶ ย้อนกลับ | ย้อนรายการที่บันทึกแล้ว ไม่ใช่ลบตัวอักษร |

ปุ่ม `S R A B D E # + ! - = /` ใต้ช่องเป็นปุ่มเติมอักขระ ไม่บันทึกทันที ปุ่มชื่อทีมเติม `*` หรือ `a` ปุ่มทีม OP#/T= เติมคำสั่งระดับทีม ส่วนปุ่ม AUTO/รหัสแนะนำทำหน้าที่เหมือน Tab

การกด Space ไม่บันทึกแรลลี่ทันที ให้กด Enter หรือ **บันทึก ↵** และตรวจข้อความ **บันทึกทั้งแรลลี่แล้ว**

## คะแนน การเสิร์ฟ และการหมุน

เมื่อบันทึกแรลลี่สำเร็จ ระบบเพิ่มหนึ่งแต้มให้ผู้ชนะ เปลี่ยนสิทธิ์เสิร์ฟ บันทึกประวัติ และหมุนเมื่อได้เสิร์ฟคืน

| สถานการณ์ | การหมุน |
| --- | --- |
| ทีมเสิร์ฟเดิมได้แต้ม | ไม่หมุน ผู้เสิร์ฟเดิมเสิร์ฟต่อ |
| ทีมรับได้แต้ม | ทีมรับได้สิทธิ์เสิร์ฟและหมุนหนึ่งตำแหน่ง |

ลำดับเมื่อได้เสิร์ฟคืนคือ **P2 → P1, P3 → P2, P4 → P3, P5 → P4, P6 → P5, P1 → P6** ผู้เล่นที่ย้ายมา P1 เป็นผู้เสิร์ฟใหม่ ไอคอนบอลควรอยู่ที่ผู้เสิร์ฟของทีมได้แต้ม

เซตทั่วไปเล่นถึงอย่างน้อย 25 แต้มและนำ 2 แต้ม เซตตัดสินตามรูปแบบที่เลือกใช้ 15 แต้มและนำ 2 แต้ม เมื่อเซตจบให้ตรวจผลและจัดไลน์อัปเซตถัดไปตามหน้าจอ

คะแนน VIS คำนวณจากเหตุการณ์ที่บันทึกใน VIS สำหรับแมตช์ตารางแข่งขัน ระบบยังแยกข้อมูล VIS จากข้อมูลทางการของ eScoreControl จึงไม่ควรถือว่าการแก้สถิติ VIS เป็นการแก้คะแนนทางการทุกส่วนหรืออันดับการแข่งขันโดยอัตโนมัติ

## เวลานอกและเปลี่ยนตัว

### เวลานอก

กด **เวลานอก** ที่ด้านล่าง Bench ของทีมที่ร้องขอ ระบบเพิ่มจำนวนครั้งของทีมนั้นในเซตปัจจุบัน ปุ่มแสดงจำนวนใช้แล้วจาก 2 ครั้ง และปิดเมื่อครบ

### เปลี่ยนตัว

1. กด **เปลี่ยนตัว** ใต้ Bench ของทีมที่ต้องการ
2. เลือกผู้เล่นออกจากผู้เล่นในสนาม
3. เลือกผู้เล่นเข้าจากรายชื่อสำรอง
4. ตรวจทีมและหมายเลข แล้วกด **ยืนยันเปลี่ยนตัว**
5. ตรวจสนามและจำนวนเปลี่ยนตัวหลังบันทึก

ปุ่มนับการเปลี่ยนตัวสูงสุด 6 ครั้งต่อทีมต่อเซต และปิดหากไม่มีสำรองหรือระบบอยู่ในโหมดล็อก การกำหนด position เป็น L ในไฟล์รายชื่อเพียงอย่างเดียวไม่ได้บันทึกการเปลี่ยนลิเบโรในประวัติ ผู้บันทึกยังต้องตรวจการใช้งานตามความสามารถของหน้าจอปัจจุบัน

## ประวัติและการย้อนรายการ

### อ่านแผงโค้ดและประวัติ

- ตัวนับด้านบนคือจำนวนรายการเหตุการณ์ ไม่จำเป็นต้องเท่ากับจำนวนแรลลี่
- **CODE** แสดงรหัสแบบกระชับ ส่วน **+ คำอธิบาย** เพิ่มรายละเอียดผู้เล่นและผล
- **รวมตามแรลลี่** รวมหลายเหตุการณ์เป็นการ์ดเดียว ยกเลิกเครื่องหมายเพื่อดูแยกรายการ
- เหตุการณ์เจ้าบ้านอยู่ซ้ายโทนน้ำเงิน ทีมเยือนอยู่ขวาโทนแดง
- ท้ายการ์ดแสดงลำดับและคะแนน โดยเรียง **เจ้าบ้าน–ทีมเยือน** แม้ทีมสลับฝั่งสนาม
- แถบคะแนนซ้ายกดเพื่อเลื่อนไปยังการ์ดนั้น ลูกศรข้าง Set ใช้เลือกเซตที่มีประวัติ
- เครื่องหมายบวก/ลบที่เหตุการณ์บอกผลของรหัส ไม่ใช่การบวกหรือลบคะแนนซ้ำอีกครั้ง
- บนจอเล็กใช้ปุ่ม **ประวัติ** เพื่อสลับจากช่องคีย์ไปดูรายการ

### ย้อนรายการที่ลงผิด

กด **↶ ย้อนกลับ** เพื่อย้อนรายการล่าสุด หากเป็นแรลลี่จะย้อนทั้งกลุ่มพร้อมคะแนน สิทธิ์เสิร์ฟ และการหมุน หากเป็นเวลานอกหรือเปลี่ยนตัวจะย้อนรายการควบคุมนั้น

ถ้าผิดหลายรายการย้อนหลัง ให้ส่งออกสำรองก่อน แล้วพิจารณาย้อนตามลำดับจากล่าสุดและคีย์ใหม่ หน้าประวัติยังไม่มีคำสั่งแก้การ์ดกลางประวัติหรือลากสลับเหตุการณ์โดยตรง

เมื่อผลยืนยันแล้วต้องเปิดตรวจแก้ไขผลก่อน และเมื่อบัญชีหรือแมตช์เป็นโหมดอ่านอย่างเดียวจะใช้ Undo ไม่ได้

## สถิติและรายงาน PDF

### ดูสถิติบนหน้าจอ

เปิด **สถิติ** จากแดชบอร์ด หรือ **📊 สถิติเต็ม** ในหน้าคีย์ ตารางรายบุคคลมีจำนวนครั้ง S/R/A/B/D/E แต้ม และเสีย พร้อมตารางสรุปเกรดของแต่ละทีม

| ค่า | วิธีอ่าน |
| --- | --- |
| จำนวนครั้ง S/R/A/B/D/E | จำนวนเหตุการณ์ทักษะนั้นที่บันทึก |
| แต้มรายบุคคล | S# + A# + B# |
| เสีย | เหตุการณ์เกรด `=` หรือ `/` |
| ตบได้แต้ม | A# |
| บล็อกได้แต้ม | B# |
| เสิร์ฟเอซ | S# |

สถิติคำนวณจากเหตุการณ์ที่ลงไว้ หากลงเฉพาะการจบแต้ม จำนวนครั้งพยายามจะไม่ครอบคลุมการเล่นทั้งหมด ควรคีย์การเล่นระหว่างแรลลี่ด้วยเมื่อต้องการวิเคราะห์ประสิทธิภาพ

### ส่งออกรายงาน

1. เปิดหน้าสถิติแล้วกด **รายงาน PDF**
2. เมื่อส่งออกจากหน้าคีย์ เลือกเพิ่มรายละเอียดรายเซตและ/หรือประวัติเหตุการณ์ได้ในหน้าต่างส่งออก
3. กด **ดาวน์โหลด PDF** แล้วรอข้อความสร้างรายงานสำเร็จ
4. เปิดไฟล์ตรวจทีม ผลเซต รายชื่อ และเวลาจัดทำก่อนส่งต่อ

รายงาน VIS ประกอบด้วย Match Result (P2) สรุปผลและตารางรายชื่อ/ไลน์อัป/แต้ม สรุปภาพรวม กราฟเปรียบเทียบแต้มตบ–เอซ–บล็อก และสถิติรายบุคคล รวมถึงสรุปผลงานในหน้า Match Result ตามข้อมูลที่มี รายงานนี้ไม่แนบหน้าสกอร์ชีตเป็นหน้าแรก

ชื่อไฟล์เป็น `Vis_match_<รหัสแมตช์>_<YYYY-MM-DD>.pdf` วันที่อ้างอิงวันส่งออกตามเวลาไทย ตัวอย่าง `Vis_match_12_2026-10-20.pdf` ช่องข้อมูลที่ไม่ได้บันทึก เช่น เจ้าหน้าที่หรือเวลาแข่งขันบางรายการ อาจแสดงขีดแทนข้อมูล

| ตัวชี้วัดในรายงาน | สูตร / ความหมาย |
| --- | --- |
| ประสิทธิภาพการตบ | (ตบได้แต้ม − ตบผิดพลาด) ÷ จำนวนตบ × 100 |
| รับเสิร์ฟเชิงบวก | (รับเกรด # + รับเกรด +) ÷ จำนวนรับเสิร์ฟ × 100 |
| ขีด `—` หรือ `-` | ไม่มีข้อมูลหรือไม่มีฐานคำนวณ |
| ศูนย์ `0` | มีข้อมูลสำหรับประเมิน แต่ไม่พบผลประเภทนั้น |

รายงานเรียงทีม A/B ตามการกำหนดฝั่งเริ่มต้น ให้ตรวจชื่อทีมในหัวตารางเสมอ เพราะอาจต่างจากลำดับซ้าย–ขวาบนสนามปัจจุบัน และต่างจากประวัติที่เรียงเจ้าบ้าน–ทีมเยือน

PDF ใช้ตรวจและส่งต่อผล ส่วน JSON ใช้สำรองและนำเข้าใหม่ ควรเก็บทั้งสองชนิดเมื่อจบงาน

## ตรวจสอบผลและเผยแพร่

### สถานะแมตช์สร้างเอง

| สถานะ | ความหมาย / ขั้นตอนถัดไป |
| --- | --- |
| ฉบับร่าง | เตรียมข้อมูลและรายชื่อ |
| พร้อมแข่งขัน | พร้อมเข้าสู่กระบวนการบันทึก |
| กำลังแข่งขัน | บันทึกแรลลี่แล้ว |
| รอตรวจสอบผล | เล่นจบ ตรวจคะแนน ประวัติ และสถิติก่อนยืนยัน |
| ยืนยันผลแล้ว | ผลถูกล็อก ต้องเปิดตรวจแก้ไขผลก่อนแก้ |
| ยกเลิก | เก็บประวัติและปิดการเผยแพร่ |

เมื่อเล่นจบ ตรวจผลเซต คะแนนรายเซต ผู้ทำแต้ม และเหตุการณ์ผิดพลาด จากนั้นกด **ตรวจสอบแล้ว · ยืนยันผล** ในแถบเครื่องมือของแมตช์สร้างเองที่รอตรวจสอบ

หากต้องแก้หลังยืนยัน เจ้าของหรือ Admin เปิด **จัดการ / เผยแพร่ → เปิดตรวจแก้ไขผล** ตรวจแก้แล้วตรวจผลและยืนยันใหม่

### เปิด Livescore สาธารณะ

1. กลับแดชบอร์ดของแมตช์สร้างเอง
2. เปิด **⋯ → จัดการ / เผยแพร่**
3. กด **เปิดเผยแพร่ Livescore สาธารณะ**
4. เปิดลิงก์สาธารณะและตรวจข้อมูลก่อนส่งให้ผู้ชม
5. เมื่อต้องการหยุดแสดงข้อมูล กด **ปิดการเผยแพร่**

หน้าสาธารณะแสดงชื่อทีม ชื่อนักกีฬา เบอร์ คะแนน และสถิติการทำแต้ม ผู้มีลิงก์เข้าดูได้โดยไม่ต้องเข้าสู่ระบบ และหน้ารีเฟรชข้อมูลประมาณทุก 3 วินาที จึงอาจมีระยะหน่วงจากหน้าผู้บันทึก

ปุ่ม **แชร์** บนหน้าคีย์เป็นลิงก์สำหรับผู้มีสิทธิ์ทำงาน ส่วน **ลิงก์สาธารณะ** เป็นลิงก์สำหรับผู้ชม การคัดลอกลิงก์หน้าคีย์ไม่ได้ให้สิทธิ์ผู้รับเพิ่ม

### ยกเลิกแมตช์

ใช้ **ยกเลิกแมตช์ (เก็บประวัติ)** ในหน้าจัดการเมื่อจำเป็น ระบบเก็บประวัติไว้และปิดการเผยแพร่ คำสั่งนี้เป็นการเปลี่ยนสถานะแมตช์ ไม่ใช่การย้อนแต้มล่าสุด แมตช์ยืนยันแล้วไม่มีปุ่มยกเลิกในสถานะนั้น

## การบันทึกและการเชื่อมต่อ

หลัง Enter ระบบส่งข้อมูลและรอผลจากเซิร์ฟเวอร์ เมื่อสำเร็จจึงล้างช่องคีย์ แสดงข้อความบันทึกแล้ว และเพิ่มประวัติ ข้อความในช่องที่ยังไม่ได้ส่งไม่ถือเป็นข้อมูลที่บันทึก

หากบันทึกไม่สำเร็จ:

1. อ่านข้อความแจ้งปัญหาและตรวจการเชื่อมต่อ
2. ตรวจประวัติว่ารายการปรากฏแล้วหรือไม่
3. หากมี **ลองส่งรายการค้างอีกครั้ง** ให้ใช้ปุ่มนั้นเพื่อส่งรายการเดิม
4. รอให้รายการค้างคลี่คลายก่อนคีย์แรลลี่ถัดไป
5. หากแจ้งว่าข้อมูลเปลี่ยน ให้ตรวจคะแนน ผู้เสิร์ฟ และไลน์อัปที่โหลดใหม่ก่อนส่งต่อ

ระบบใช้รหัสรายการเพื่อช่วยป้องกันบันทึกซ้ำเมื่อส่งรายการเดิมอีกครั้ง สำหรับแมตช์โหมดเซิร์ฟเวอร์ รายการค้างเป็นตัวช่วยส่งซ้ำ ส่วนโหมด Offline เก็บแมตช์และคิวคำสั่งใน IndexedDB ตามขั้นตอนด้านล่าง

### เตรียม Offline ครั้งแรก

1. เปิด production build ผ่าน HTTPS หรือ localhost และเข้าสู่ระบบออนไลน์ด้วยบัญชี Admin หรือผู้บันทึก VIS
2. เปิดแดชบอร์ด กดไอคอนเมฆขีดทับ **VIS Offline** ถัดจาก **นำเข้า JSON** แล้วรอข้อความ **เก็บไฟล์แอปสำหรับ Offline แล้ว** หากใช้ Vite dev server จะยังไม่ติดตั้ง PWA
3. เปิด **เตรียมเครื่อง / ต่ออายุสิทธิ์ / ปลดล็อก** ตั้ง PIN ตัวเลข 6–12 หลัก แล้วกด **เตรียมสิทธิ์ 7 วัน**
4. ติดตั้งแอปจากเมนูเบราว์เซอร์ได้ หรือใช้เว็บไซต์เดิมในเบราว์เซอร์เดิม
5. ทดลองตัดการเชื่อมต่อ เปิดหน้า Login แล้วใช้ **เปิด VIS แบบ Offline ด้วย PIN** ก่อนนำไปใช้งานจริง

ต้องเตรียมออนไลน์ครั้งแรก การปลดล็อก Offline ไม่ส่ง PIN ไปยังเซิร์ฟเวอร์และไม่ใช้แทนรหัสผ่านบัญชีเมื่อซิงค์ เมื่อสิทธิ์หมดอายุยังใช้ PIN เดิมผ่านปุ่ม **ปลดล็อกเพื่อสำรองข้อมูล** เพื่อเปิดรายการและส่งออก JSON ได้ แต่ต้องต่ออายุออนไลน์ก่อนบันทึกหรือซิงค์ หากลืม PIN สามารถตั้งใหม่หลังยืนยันบัญชีออนไลน์

### สร้างและบันทึกในเครื่อง

1. กด **ทำงานในเครื่อง** บนแดชบอร์ด
2. ใช้ **สร้างแมตช์ใหม่** หรือนำเข้าไฟล์สำรองตามขั้นตอนปกติ
3. จัดรายชื่อ ไลน์อัป และคีย์แรลลี่ ระบบคำนวณคะแนนและหมุนในเครื่อง
4. ตรวจจำนวนคำสั่งรอซิงค์จากแผง **VIS Offline** บนแดชบอร์ด
5. กลับแดชบอร์ดแล้วใช้ **สำรอง JSON** เป็นระยะ

จำนวนรอซิงค์นับคำสั่ง เช่น ไลน์อัป แรลลี่ เวลานอก เปลี่ยนตัว หรือ Undo ไม่ใช่จำนวนแต้ม ข้อมูลที่เพิ่งพิมพ์แต่ยังไม่กด Enter ไม่เข้าในคิว

### นำแมตช์เซิร์ฟเวอร์ไปทำงาน Offline

กลับโหมดเซิร์ฟเวอร์ เลือกแมตช์ใน **นำแมตช์สร้างเองบนเซิร์ฟเวอร์มาทำงาน Offline** ระบบจะเก็บข้อมูลในเครื่องและจองสิทธิ์เครื่องหลัก 7 วัน ระหว่างจอง เครื่องอื่นและหน้าคีย์ออนไลน์จะไม่สามารถแก้แมตช์นั้นได้

รุ่นนี้รองรับแมตช์สร้างเอง ยังไม่นำตารางแข่งขันหลักจาก Admin ไปบันทึก Offline หนึ่งแมตช์ใช้เครื่องหลักหนึ่งเครื่อง การย้ายงานให้ซิงค์และคืนสิทธิ์ก่อน แล้วให้อีกเครื่องรับงาน ห้ามคัดลอกฐานข้อมูลเบราว์เซอร์ไปทับอีกเครื่อง

### ซิงค์เมื่อมีอินเทอร์เน็ต

1. กลับแดชบอร์ด หากต้องยืนยันบัญชีใหม่ กด **เข้าสู่ระบบออนไลน์เพื่อซิงค์** และใช้บัญชีเจ้าของข้อมูลเดิม
2. กด **ซิงค์** เพื่อส่งข้อมูลและทำงานในเครื่องต่อ หรือ **ซิงค์และคืนสิทธิ์** เมื่อต้องการกลับไปทำงานบนเซิร์ฟเวอร์
3. รอข้อความสำเร็จและตรวจจำนวนค้างเป็นศูนย์ ระหว่างซิงค์ระบบกันการบันทึกเพิ่มในแมตช์นั้น
4. หากสัญญาณหลุด ให้กดส่งซ้ำ ระบบใช้รหัสคำสั่งเดิมเพื่อตรวจข้อมูลซ้ำ
5. หลังคืนสิทธิ์ ยังส่งออกสำเนาจากรายการในเครื่องได้ ใช้ **เปิดบนเซิร์ฟเวอร์** เพื่อตรวจสอบ ยืนยันผล หรือเผยแพร่

ระบบแบ่งคิวเป็นชุดละไม่เกิน 100 คำสั่ง และจำกัดขนาดข้อมูลต่อคำขอ จึงส่งคิวสะสมเกิน 5,000 คำสั่งได้ แต่ละชุดที่เซิร์ฟเวอร์ยืนยันแล้วจะถูกนำออกจากคิว หากสัญญาณหลุดกลางทาง ชุดที่ยังไม่ยืนยันจะอยู่ในเครื่องและส่งซ้ำด้วยรหัสเดิม การคืนสิทธิ์จะเกิดเฉพาะชุดสุดท้าย

ระหว่างดาวน์โหลดหรือซิงค์ ห้ามเปิดบันทึกแมตช์เดียวกันจากหลายแท็บ ระบบจะล็อกและปฏิเสธการดาวน์โหลดทับงานที่ยังรอซิงค์ ข้อมูล Scorer ถูกส่งพร้อมการจองสิทธิ์จากเซิร์ฟเวอร์ใน transaction เดียวกัน หากจองสำเร็จแต่บันทึกลงเครื่องล้มเหลว ระบบจะพยายามคืนเฉพาะสิทธิ์ที่เพิ่งจอง หากคืนไม่ได้ให้เชื่อมต่อแล้วดาวน์โหลดแมตช์เดิมอีกครั้งด้วยบัญชีและเบราว์เซอร์เดิม

### สำรองและนำกลับเข้า ScorerControl

หน้า **ScorerControl · แมตช์ในเครื่อง** (`/scorer-offline`) มีปุ่ม **สำรอง JSON** และช่อง **นำเข้าไฟล์สำรอง Scorer JSON** โดยแยกจากรูปแบบไฟล์ VOLLEY VIS

1. ปลดล็อก PIN ของบัญชีเจ้าของไฟล์ก่อนนำเข้า รองรับไฟล์ JSON ไม่เกิน 64 MB
2. ระบบตรวจบัญชี รูปแบบแมตช์ และคิวคำสั่ง และไม่เขียนทับแมตช์ที่มีอยู่แล้วในเครื่อง
3. ไฟล์จากเครื่องหลักเดิมสามารถกู้แมตช์ที่ไม่มีในฐานข้อมูลเบราว์เซอร์แล้วได้ โดยเก็บรหัสคำสั่งเดิมสำหรับส่งซ้ำ
4. ไฟล์จากเครื่องอื่นหรือหลังเปลี่ยนรหัสเครื่องจะเก็บเพื่ออ่านรายการและส่งออกสำรองเท่านั้น ไม่สามารถบันทึกหรือซิงค์แทนเครื่องหลักเดิมได้
5. หลังนำเข้า ตรวจจำนวนคำสั่ง คะแนน และบัญชี ก่อนซิงค์หรือกลับไปบันทึก

หากแจ้งข้อมูลขัดแย้ง ระบบไม่เขียนทับอัตโนมัติ เลือก **สร้างสำเนาเป็นแมตช์ใหม่** เพื่อรักษางานในเครื่อง หรือ **สำรองแล้วใช้ข้อมูลเซิร์ฟเวอร์** ซึ่งจะดาวน์โหลดสำรองและขอให้ยืนยันก่อนแทนที่คิวในเครื่อง หากอีกเครื่องยังจองสิทธิ์อยู่ ต้องคืนสิทธิ์จากเครื่องนั้นหรือเก็บเป็นสำเนาใหม่

### การเผยแพร่และการเก็บรักษาข้อมูล

แมตช์ Offline ยืนยันผลและเปิดเผยแพร่จากสำเนาในเครื่องไม่ได้ ต้องซิงค์ คืนสิทธิ์ และตรวจบนเซิร์ฟเวอร์ก่อน Livescore แสดงเฉพาะข้อมูลที่เซิร์ฟเวอร์ได้รับ พร้อมเวลาปรับปรุง จึงไม่แสดงแต้มที่ยังอยู่ในคิวเครื่อง

IndexedDB เก็บข้อมูลเฉพาะเบราว์เซอร์และโปรไฟล์นี้ ระบบขอสิทธิ์เก็บข้อมูลถาวรจากเบราว์เซอร์ แต่ไม่ใช่การสำรองไฟล์ การล้างข้อมูลเว็บไซต์ โหมดไม่ระบุตัวตน หรือเครื่องเสียอาจทำให้ข้อมูลหาย ให้เก็บ JSON แยกไว้นอกเบราว์เซอร์เสมอ ไฟล์วิดีโอในเครื่องใช้ได้ตามที่เบราว์เซอร์รองรับ ส่วน YouTube และวิดีโอบนเว็บยังต้องมีอินเทอร์เน็ต

หากมีหลายเครื่องเปิดแมตช์เดียวกัน ควรตกลงผู้บันทึกหลักและแบ่งหน้าที่ให้ชัด เพราะการเปลี่ยนคะแนนหรือไลน์อัปจากอีกเครื่องอาจทำให้ข้อมูลที่กำลังคีย์ใช้ต่อไม่ได้

## แบบฝึกหัดและรายการตรวจสอบ

### ทดลองคีย์ก่อนใช้งานจริง

สร้างแมตช์ฝึกแยกไว้เป็นส่วนตัว จัดผู้เล่นทั่วไปครบ 6 คนต่อทีม และให้ THA #3 เป็น P1 เสิร์ฟก่อน

1. กด Tab ตามด้วย `#` แล้ว Enter: ตรวจว่า THA ได้แต้มและผู้เสิร์ฟยังคนเดิม
2. กด Tab ตามด้วย `=` แล้ว Enter: ตรวจว่า JPN ได้แต้ม หมุน และบอลย้ายไป P1 ใหม่ของ JPN
3. กดย้อนกลับ: ตรวจว่าคะแนนและไลน์อัปกลับไปก่อนเสิร์ฟเสีย
4. คีย์ `*03S a10A#` โดยให้ JPN #10 อยู่ในสนาม เลือกรหัสคู่แล้ว Enter: ตรวจว่าเพิ่มให้ JPN หนึ่งแต้ม
5. ขอเวลานอก เปลี่ยนตัวหนึ่งครั้ง แล้วตรวจประวัติและจำนวนครั้ง
6. ส่งออก JSON และ PDF แล้วเปิดตรวจทั้งสองไฟล์
7. นำเข้า JSON เป็นแมตช์ใหม่ ตรวจคะแนนและประวัติเทียบต้นฉบับ
8. ทดลองเปิดและปิดเผยแพร่ แล้วตรวจด้วยลิงก์ผู้ชม

### PIN และการเข้าสู่ระบบตาม role

PIN ของเครื่องเป็นชุดเดียว ใช้ปลดล็อกทั้ง VIS และ ScorerControl ตามสิทธิ์ของบัญชี ไม่ต้องตั้ง PIN แยกสองระบบ

**ใช้หน้าเข้าสู่ระบบเดียวที่ `/login`**

| Role | หลังเข้าสู่ระบบออนไลน์ | หลังปลดล็อก Offline |
| --- | --- | --- |
| Admin | `/admin` | `/adminvis` |
| Statistician | `/adminvis` | `/adminvis` |
| Score / Scorer | `/adminscorer` | `/scorer-offline` |
| Referee | `/adminscorer` | ไม่รองรับ PIN Offline |

หน้า Login มีฟอร์มเข้าสู่ระบบออนไลน์และตัวเลือก **Offline PIN · VIS / ScorerControl** ใช้บัญชีและ PIN เดิมร่วมกัน เมื่อสำเร็จจะเข้าหน้าหลักตาม role ทันที

หากเปิดลิงก์แมตช์ที่บัญชีไม่มีสิทธิ์ ระบบจะแสดงข้อความที่หน้า Login และให้เข้าสู่ระบบด้วยบัญชีที่มีสิทธิ์

1. เปิดหน้า Login แล้วกด **Offline PIN · VIS / ScorerControl** ใส่ PIN ที่เตรียมไว้
2. ระบบจะเข้าหน้ารายการ Offline ตาม role ในตารางด้านบนโดยตรง
3. หากเปิดจากลิงก์ของระบบใด จะกลับไประบบนั้น หากเป็นลิงก์แมตช์ Offline จะเปิดได้เมื่อพบข้อมูลที่เตรียมไว้และยังไม่ได้คืนสิทธิ์ มิฉะนั้นจะกลับหน้ารายการของระบบนั้น
4. เมื่อต้องเปลี่ยนบัญชี ใช้ **เข้าสู่ระบบออนไลน์ / ต่ออายุ PIN** หรือออกจากระบบแล้วเข้าสู่ระบบใหม่

PIN ไม่ใช่การเข้าสู่ระบบเซิร์ฟเวอร์ เมื่อจะซิงค์ให้เข้าสู่ระบบออนไลน์ด้วยบัญชีเจ้าของข้อมูล หากปลดล็อก PIN ของคนละบัญชีกับเซสชันออนไลน์เดิม ระบบจะล้างเซสชันออนไลน์เดิมและใช้บัญชีเจ้าของ PIN โดยไม่ลบแมตช์ที่เก็บในเครื่อง

### ลำดับ PIN Offline และการแก้ปัญหาเข้าใช้งาน

PIN ถูกต้องและบัญชีมีสิทธิ์ ต้องเข้าหน้ารายการของระบบที่เลือกได้แม้ยังไม่มีแมตช์ การเปิดแมตช์เป็นการตรวจอีกขั้นหนึ่ง

1. เปิดแอปออนไลน์ครั้งแรกผ่าน HTTPS หรือ localhost เตรียม PWA ให้พร้อม แล้วเข้าสู่ระบบด้วยบัญชีที่จะบันทึกการแข่งขัน
2. ในแผง Offline เลือกเตรียมหรือต่ออายุสิทธิ์ กรอก PIN และยืนยัน PIN ให้ตรงกัน การเตรียมไม่เปลี่ยนโหมดทำงานโดยอัตโนมัติ
3. ดาวน์โหลดและจองเฉพาะแมตช์ที่ต้องการใช้งาน Offline ตรวจชื่อบัญชีและสำรอง JSON
4. เปิด `/login` แล้วเลือก Offline PIN ตรวจชื่อบัญชีเจ้าของ PIN และวันหมดอายุก่อนกรอก
5. ระบบตรวจ PIN วันหมดอายุและสิทธิ์ระบบปลายทางก่อนสร้างเซสชัน หากไม่ผ่าน จะไม่เปลี่ยนบัญชีหรือโหมดเดิม
6. หลังผ่าน Admin และ Statistician เข้าหน้า VIS ส่วน Score / Scorer เข้ารายการแมตช์ ScorerControl ในเครื่อง
7. หากเข้าจากลิงก์แมตช์ ระบบจะตรวจข้อมูลที่ดาวน์โหลดไว้ แมตช์ที่ไม่พบ คืนสิทธิ์แล้ว หรือเป็นข้อมูลจากเครื่องอื่น จะกลับหน้ารายการพร้อมข้อความเหตุผล
8. เมื่อมีสัญญาณกลับมา ระบบไม่ย้ายหน้าและไม่เปลี่ยนโหมดเอง ให้เข้าสู่ระบบออนไลน์ด้วยบัญชีเจ้าของข้อมูล แล้วกดซิงค์ ตรวจจำนวนรายการค้างและเวลาซิงค์ล่าสุด

**ข้อกำหนดบัญชีและข้อมูล**

- หนึ่งบัญชี Offline ต่อโปรไฟล์เบราว์เซอร์ ใช้ PIN ร่วมระหว่าง VIS และ ScorerControl ตามสิทธิ์
- เปลี่ยน PIN หรือต่ออายุบัญชีเดิมไม่ลบแมตช์และคิวซิงค์ PIN ใหม่แทน PIN เดิมทั้งสองระบบ
- เปลี่ยนไปเตรียมบัญชีอื่นต้องยืนยันว่าได้สำรองแล้ว และระบบจะปฏิเสธหากฐานข้อมูลใดมีคำสั่งรอซิงค์หรือแมตช์สร้างใหม่ที่ยังไม่ขึ้นเซิร์ฟเวอร์
- การเปลี่ยนบัญชีไม่ลบข้อมูลเดิม ข้อมูลของบัญชีเดิมยังแยกเจ้าของ ต้องกลับมาเตรียมสิทธิ์บัญชีเดิมเพื่อใช้งานข้อมูลนั้น
- หลังปลดล็อก บัญชีจาก PIN เป็นตัวตนหลักของโหมด Offline แม้มีเซสชันออนไลน์เก่า หากบัญชีออนไลน์เดิมต่างกันจะล้างเซสชันออนไลน์เดิม
- สิทธิ์ Offline หมดอายุจะล็อกหน้า ไม่ใช้โทเคนเก่าพาไปหน้าอื่นเงียบ ๆ ให้ต่ออายุออนไลน์ด้วยบัญชีเดิม ข้อมูลที่บันทึกยังอยู่
- สถานะบัญชี สถานะเครือข่ายเครื่อง และจำนวนคำสั่งรอซิงค์เป็นคนละเรื่อง มีเครือข่ายไม่ได้ยืนยันว่าเซิร์ฟเวอร์ติดต่อได้หรือซิงค์แล้ว

| อาการ | การดำเนินการ |
| --- | --- |
| แจ้งยังไม่เตรียม Offline | เตรียมสิทธิ์ออนไลน์ในเบราว์เซอร์และโปรไฟล์เดิมก่อน |
| PIN ไม่ถูกต้อง | ตรวจชื่อบัญชีบนฟอร์ม และใช้ PIN ล่าสุดที่ตั้งจากระบบใดระบบหนึ่ง |
| สิทธิ์หมดอายุ | เข้าออนไลน์ด้วยบัญชีเดิม แล้วเตรียมหรือต่ออายุ PIN ใหม่ |
| PIN ถูกแต่ไม่มีสิทธิ์ VIS | เปลี่ยนไปหน้า ScorerControl หรือใช้บัญชีที่มีสิทธิ์ ไม่ต้องตั้ง PIN ซ้ำ |
| ปลดล็อกแล้วรายการว่าง | ยังไม่ได้ดาวน์โหลดแมตช์ของบัญชีนี้ ไม่ใช่การปลดล็อกล้มเหลว |
| อ่านข้อมูลในเครื่องไม่ได้ | กดอ่านใหม่ ปิดแท็บอื่นที่อาจล็อกฐานข้อมูล และตรวจพื้นที่จัดเก็บ ห้ามล้างข้อมูลเว็บไซต์เพื่อแก้ปัญหา |
| แมตช์คืนสิทธิ์แล้ว | สำรองจากรายการในเครื่อง และเปิดแมตช์บนเซิร์ฟเวอร์หลังเข้าสู่ระบบออนไลน์ |
| เปลี่ยนบัญชีไม่ได้เพราะมีงานรอซิงค์ | ใช้ PIN บัญชีเดิมสำรองและซิงค์งานให้ครบก่อน |
| ซิงค์ไม่ได้แม้ใส่ PIN ผ่าน | PIN ไม่ใช่การล็อกอินเซิร์ฟเวอร์ ให้เข้าสู่ระบบออนไลน์ด้วยบัญชีเจ้าของแมตช์ |
