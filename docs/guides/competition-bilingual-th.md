# สร้างรายการแข่งขันสองภาษา

หน้า Admin > รายการแข่งขัน > สร้างรายการแข่งขัน แบ่งเป็น 4 ขั้นตอน:

1. ชื่อทางการไทยและอังกฤษ ชื่อย่อ คำอธิบาย และโลโก้
2. วันเริ่ม–สิ้นสุด (ค.ศ.) และสนามหลัก
3. ตารางเลือกคู่รุ่นอายุ–ประเภททีม โดยสร้างเฉพาะช่องที่เลือก
4. กติกากลาง ตัวเลือกจำนวนเซตเฉพาะประเภท สถานะรับสมัคร และตัวอย่าง TH/EN

ก่อนสร้างต้องมีชื่อทั้งสองภาษา วันที่ถูกต้อง สนาม และอย่างน้อยหนึ่งประเภทแข่งขัน ระบบตรวจข้อมูลซ้ำและบันทึกรายการย่อยใน transaction เดียว รายการที่มีอยู่แล้วจะถูกข้ามและแจ้งจำนวน

การแก้ไขใช้รายการย่อยเดิมและ ID เดิม เพื่อคงความสัมพันธ์กับทีมและแมตช์ ชื่อเดิมยังเป็น fallback สำหรับข้อมูลเก่าที่ไม่มีคำแปล ไม่มีการแปลชื่อเฉพาะอัตโนมัติ

ปุ่ม **บันทึกร่างบนอุปกรณ์นี้** เก็บใน localStorage แยกตามผู้ใช้และรายการ ไม่สร้างรายการแข่งขันบนเซิร์ฟเวอร์ ไม่ซิงก์ข้ามเครื่อง ใช้ **เรียกคืนร่าง** เพื่อเปิดต่อ และลบร่างอัตโนมัติหลังบันทึกสำเร็จ

ชื่อสองภาษาใช้ในหน้าจัดการรายการ ตัวเลือกสมัครทีม หน้าจัดการทีม ข้อมูลแมตช์/scorer และรายงานที่อ้างอิงชื่อรายการ ส่วน Team composition แสดงชื่อทั้งสองภาษาพร้อมกัน

## ฐานข้อมูล

ใช้เฉพาะ migration 39:

```powershell
cd backend
node scripts/migrateCompetitionNames.js --apply
```

Migration เพิ่มคอลัมน์ชื่อ/ชื่อย่อ/คำอธิบายของรายการและชื่อสองภาษาของทะเบียนสนาม/รุ่นอายุ เก็บชื่อเดิมไว้ และเติมเฉพาะภาษาที่ตรวจได้จากชื่อเดิมโดยไม่สร้างคำแปล รันซ้ำได้ ต้องใช้ก่อนเริ่ม backend เวอร์ชันใหม่บนเครื่องอื่น

## ตรวจสอบ

```powershell
cd backend
node --test tests/competitionInput.test.js tests/competitionCreation.test.js
$env:RUN_COMPETITION_DB_TESTS='1'
node --test tests/competitionNames.mysql.test.js
cd ../client
node --test src/utils/i18n/competitionNames.test.js
npm.cmd run lint
npm.cmd run build
```

ทดสอบ MySQL ใช้ตารางชั่วคราว ไม่สร้างแถวรายการจริง ทดสอบเบราว์เซอร์ด้วย `node scripts/checkCompetitionWizard.mjs` โดยติดตั้ง Playwright หรือกำหนด `PLAYWRIGHT_MODULE_PATH` และ `CHROME_BIN` ใช้ fixture ที่ไม่เรียก API จริงและไม่ต้องเปิด dev server
