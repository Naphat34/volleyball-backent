# คู่มือ ScorerControl Offline

รองรับการนำแมตช์จากระบบลงมาบันทึกบนเครื่องหลัก ใช้หน้าคะแนน กติกา การหมุน ลิเบโร เวลานอก เปลี่ยนตัว บทลงโทษ และการจบเซตของ ScorerConsole เดิม แล้วกดซิงค์กลับฐานข้อมูลเมื่อเชื่อมต่อ ไม่สร้างคะแนนซ้ำจาก VIS

## เริ่มใช้งาน

หน้า `/adminscorer` ใช้แดชบอร์ดโทนเข้มแบบ VIS แสดงแมตช์ในรายการที่เปิดอยู่ทันที ค้นหาชื่อทีม หมายเลขแมตช์ สนาม หรือรอบการแข่งขันได้ และกรองรายการ สถานะ ทีม พร้อมเรียงหัวตารางและเลือก 10/25/50 รายการต่อหน้า

กด **บันทึกคะแนน** เพื่อเข้า ScorerControl, **ข้อมูลแมตช์** เพื่อเปิดรายละเอียด หรือ **⋯** เพื่อดู Livescore/ส่งออกรายงาน PDF บัญชีผู้ตัดสินเปิดดูข้อมูลได้โดยไม่มีปุ่มบันทึกคะแนน ไอคอนเมฆขีดทับบนแถบเมนูเปิดข้อมูล Offline และทางเข้ารายการแมตช์ในเครื่อง

1. ผู้ดูแลติดตั้ง migration 33 ด้วย `node backend/scripts/migrateScorerOffline.js` และรีสตาร์ต Backend
2. ใช้ production build ผ่าน HTTPS หรือ localhost รอ PWA ติดตั้งไฟล์แอปสำเร็จขณะมีอินเทอร์เน็ต Vite dev server ไม่เก็บแอปสำหรับเปิด Offline
3. เข้าสู่ระบบด้วยบัญชีที่มีสิทธิ์ Scorer เปิดแมตช์และเตรียมรายชื่อให้ครบ
4. กด **☁ Offline** บนหัว Scorer Console ตั้ง PIN ตัวเลข 6–12 หลัก แล้วกด **เตรียม / ต่ออายุสิทธิ์** สิทธิ์ใช้ได้ 7 วัน
5. รอคิวเหตุการณ์ออนไลน์ของแมตช์นี้ส่งครบ แล้วกด **ดาวน์โหลดและจองแมตช์ Offline** ระบบบันทึกสถานะล่าสุด ดาวน์โหลดข้อมูล และจองสิทธิ์เครื่องหลัก จากนั้นโหลดหน้าคะแนนใหม่
6. เมื่อไม่มีอินเทอร์เน็ต เปิดหน้า Login ที่ `/login?scorer-offline=1` ปลดล็อกด้วย PIN แล้วเลือกรายการจาก `/scorer-offline`

เริ่มช่วง Offline จะเริ่มประวัติ Undo ใหม่ เพื่อป้องกันย้อนแก้เหตุการณ์ทางการก่อนดาวน์โหลด ไม่ลบเหตุการณ์เดิมบนเซิร์ฟเวอร์

## การบันทึกในเครื่อง

ใช้หน้าคะแนนตามปกติ แถบสถานะแสดง **Offline · เครื่องหลัก** และ **บันทึกในเครื่อง** ตัวเลขบนปุ่ม Offline แสดงจำนวนคำสั่งรอซิงค์ ซึ่งรวมเหตุการณ์ ไลน์อัป รายชื่อ การตั้งค่า และสแนปช็อต ไม่เท่ากับจำนวนแต้ม

คำสั่งเก็บใน IndexedDB โดยผูกบัญชี ส่วนข้อมูลกู้หน้าจอเดิมยังใช้ localStorage และเก็บสำเนาในรายการ Offline ด้วย อย่าล้างข้อมูลเว็บไซต์หรือใช้โหมดไม่ระบุตัวตนระหว่างงาน ใช้ **สำรอง JSON** เก็บไฟล์ออกนอกเบราว์เซอร์เป็นระยะ ไฟล์ ScorerControl เป็นคนละรูปแบบกับไฟล์ VIS จึงไม่ให้นำเข้าผ่านปุ่ม JSON ของ VIS

สแนปช็อตที่เกิดติดกันจากนาฬิกาจะรวมเป็นสถานะล่าสุดก่อนส่ง เพื่อลดขนาดคิว เมื่อเริ่มส่งแล้วจะรักษารหัสและข้อมูลคำสั่งเดิมไว้จนได้รับใบรับ หากสัญญาณขาดหลังเซิร์ฟเวอร์บันทึกแล้ว ระบบตรวจรหัสและลายนิ้วมือคำสั่งเพื่อรับช่วงต่อโดยไม่เพิ่มแต้มซ้ำ

สามารถบันทึกการแข่งขันและโหลดหน้าใหม่เพื่อทำต่อได้ แต่คำขอจากเครื่องเจ้าหน้าที่ทีม การเพิ่มหรือแก้ทะเบียนนักกีฬารายคน และข้อมูลที่ไม่ได้ดาวน์โหลดต้องใช้ออนไลน์ ให้เตรียมรายชื่อและเจ้าหน้าที่ก่อนออก Offline

Undo คืนสถานะที่เกิดขึ้นในช่วง Offline นี้ เมื่อซิงค์ เซิร์ฟเวอร์ลบเฉพาะเหตุการณ์ของช่วง Offline ที่ถูกย้อน และรักษาเหตุการณ์ก่อนดาวน์โหลดไว้

## ซิงค์และคืนสิทธิ์

1. เชื่อมต่ออินเทอร์เน็ต หากหมดช่วงเข้าสู่ระบบ ให้ใช้ลิงก์ **เข้าสู่ระบบออนไลน์ / ปลดล็อกด้วย PIN** และเข้าสู่ระบบด้วยบัญชีเดิม
2. กลับแมตช์ เปิด **Offline** แล้วกด **ซิงค์** หากต้องการทำงานในเครื่องต่อ หรือ **ซิงค์และคืนสิทธิ์** เพื่อกลับไปบันทึกออนไลน์
3. ระหว่างทำรายการ หน้าคะแนนจะล็อกชั่วคราวเพื่อป้องกันการเพิ่มคำสั่งระหว่างส่ง
4. ตรวจว่าจำนวนค้างเป็นศูนย์ หากสัญญาณขาด กดส่งซ้ำได้ ระบบใช้รหัสคำสั่งเดิมและใบรับจากเซิร์ฟเวอร์ จึงไม่เพิ่มแต้มซ้ำ
5. หลังคืนสิทธิ์ หน้าจะโหลดข้อมูลออนไลน์ใหม่

หนึ่งแมตช์จองเครื่องหลักได้หนึ่งเครื่องเป็นเวลา 7 วัน การเขียนจาก Scorer เครื่องอื่นถูกปฏิเสธระหว่างจอง หากข้อมูลทางการหรือรายชื่อเปลี่ยนระหว่าง Offline การซิงค์จะหยุดโดยไม่เขียนทับ ให้สำรอง JSON และให้ผู้ดูแลตรวจเทียบข้อมูลก่อนจัดการ ไม่ควรย้ายฐานข้อมูลหรือไฟล์สำรองไปทำงานพร้อมกันสองเครื่อง

## จบแมตช์และยืนยันผล

จบเกมในเครื่องได้ แต่การซิงค์ผลจบเกมยังเป็น **รอตรวจสอบ** บนเซิร์ฟเวอร์ ไม่ยืนยันผลทางการอัตโนมัติ

หลัง **ซิงค์และคืนสิทธิ์** ตรวจคะแนนรายเซต ประวัติ รายชื่อ และลายเซ็น แล้วกด **ตรวจสอบแล้ว · ยืนยันผลทางการ** ในแผง Offline จึงเปลี่ยนเป็นผลเสร็จสมบูรณ์ การส่งชุดเดิมซ้ำหลังยืนยันจะไม่เปิดผลกลับมาใหม่

Livescore เห็นเฉพาะสถานะที่ซิงค์สำเร็จ การเล่น Offline ที่ยังอยู่ในคิวไม่ส่งสดให้ผู้ชม และไม่มีการส่ง POINT จาก VIS มาบวกคะแนนทางการซ้ำ

## สำหรับผู้ดูแลระบบ

Migration 33 เพิ่มเฉพาะตาราง `scorer_offline_sessions` เก็บเจ้าของ เครื่องหลัก ลายนิ้วมือข้อมูล คำสั่งที่รับแล้ว และจุดตรวจคะแนน ไม่เปลี่ยนทะเบียนทีมหลักด้วยตัว migration

การซิงค์ล็อกแถวแมตช์ ตรวจลายนิ้วมือข้อมูลทางการและรายชื่อ แล้วเล่นคำสั่งผ่านตัวจัดการ Scorer เดิมบน connection เดียว โดยระงับ commit และ Socket ระหว่างทาง ทั้งชุด commit พร้อมกันเมื่อผ่านทุกคำสั่ง หากผิดจะ rollback ทั้งชุด เซิร์ฟเวอร์ตรวจคะแนน POINT ทีละหนึ่งแต้ม คะแนนสแนปช็อต กติกาจบเซต และ Undo ที่อ้างอิงจุดตรวจที่เคยเกิดขึ้น

ตัวตรวจ Offline เพิ่มเติมไม่ได้แทนการตรวจทุกรายละเอียดของกติกาลิเบโรหรือบทลงโทษในหน้าคะแนน การทดสอบหน้างานต้องครอบคลุมกติกาเฉพาะรายการด้วย

```powershell
cd client
npm.cmd run lint
npm.cmd run test:unit
npm.cmd run build
npm.cmd run test:pwa
cd ../backend
node --test tests/scorerOfflineRules.test.js
$env:RUN_MYSQL_SCORER_OFFLINE='1'
node --test tests/scorerOffline.mysql.test.js
Remove-Item Env:RUN_MYSQL_SCORER_OFFLINE
```

MySQL integration ใช้ตารางชั่วคราวและอาศัยแมตช์ที่มีอยู่เป็นตัวอย่างรายชื่อแบบอ่านอย่างเดียว ไม่แก้แมตช์จริง ทดสอบก่อนใช้จริงบน production build: ดาวน์โหลด ตัดเน็ต ปลดล็อก ลงแต้ม/หมุน/ลิเบโร/เปลี่ยนตัว/บทลงโทษ โหลดหน้าใหม่ Undo จบเซตและแมตช์ สำรอง เชื่อมต่อ ซิงค์ซ้ำ คืนสิทธิ์ และยืนยันผล
